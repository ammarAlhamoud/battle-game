Its near-victory import is generated by the real simulation with the legal initial three-point skill purchase. The bilingual scenario covers the campaign, mission briefing, skills, settings, production, selection, orders and defeat/results. English can be restored from settings, and Arabic persists after reload. The language controls support Tab, arrow keys, Home and End. A deep comparison of the paused battle before and after language switching confirms that units, orders, production, resources, fog, AI state and reward records remain unchanged.

RTL campaign layouts were checked at 1440, 1100, 768 and 375 CSS pixels without horizontal page overflow. The battle interface was also checked at 1100 × 760. The game remains intended for desktop mouse/keyboard play; a narrow campaign layout does not establish touch RTS support.

## Offline regression

The production test downloads all eight era illustrations, turns the browser context offline, reloads the page, switches to Arabic, verifies both Arabic font weights, opens another era illustration and resumes the saved battle with its simulation Worker. It then returns online and verifies campaign progression from a real result.

This test found a real cache-matching defect: static hosts can emit `Vary: Origin`, while precache requests and module/stylesheet requests differ. The Service Worker now ignores that variation only for its explicitly listed, same-origin static assets. The complete offline regression passes after the correction. Cache revisions include the cache-generator source as well as the distributed files.

## Reproduce

Node 24.19.0, npm 11.9.0 and system Chromium 154 were used. Install dependencies and compile the simulation used by the test runners:

```sh
npm ci
npm test
npm run build
```

Keep a development server and a production preview running in separate terminals:

```sh
npm run dev -- --port 5173
```

```sh
npm run preview -- --port 4173
```

Run the browser checks from a third terminal:

```sh
npm run test:storage
npm run test:localization
node scripts/simulate-campaign.mjs --mission=e1m1 --basic-skills
npm run test:browser
```

The fixture-generation step creates `test-results/late-victory.json`, required by the production scenario. The storage and localization scripts use the development server; the production scenario uses the preview server. Browser scripts use fresh isolated contexts, keeping their corruption/import experiments away from an existing player's saves. Set `CHROMIUM_PATH` when Chromium is installed elsewhere. The gameplay and localization scripts also accept `GAME_URL`; retain the default development URL for the browser's missing-translation instrumentation.

Browser reports and screenshots are written under ignored `test-results/`. Representative images are retained in [screenshots](screenshots/): [Arabic campaign](screenshots/campaign-ar.png) and [Arabic battle](screenshots/battle-ar.png).

Optional campaign and performance checks:

```sh
npm run test:campaign -- --all
npm run test:campaign -- --skills
npm run benchmark
```

## Performance and remaining limits

[PERFORMANCE.md](PERFORMANCE.md) records CPU timing and memory methodology. On the shared server, 40-unit encounters averaged 9.602 ms per simulation tick; the synthetic 200-unit workload averaged 46.416 ms, with occasional ticks exceeding the 100 ms simulation budget. The extended test simulated 500 seconds with ongoing movement/combat and naturally completed battles. These numbers exclude browser rendering.

A separate headless software-WebGL renderer sample at 1280 × 800 CSS pixels, adaptively rendering at 832 × 520, measured 37.17 FPS for an ordinary scene and 27.85 FPS for a synthetic 240-unit rendering load. The ordinary frame-time 95th percentile was 50 ms; the heavy sample's was 66.6 ms. The five-second renderer harness stepped simulation at 10 Hz without AI; it is not a representative hardware or full-game benchmark.

The requested 60 FPS ordinary / 30 FPS heavy targets on a mid-range desktop remain unverified. Real-GPU performance, exhaustive human campaign balance, every skill combination and arbitrary adversarial congestion remain outside the completed checks. Campaign viability and economic conservation results are detailed in [BALANCE.md](BALANCE.md). No hardware frame-rate guarantee is inferred from the cloud CPU tests.
